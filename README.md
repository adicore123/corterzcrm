# Cortez CRM

מערכת תפעול בעברית לניהול תיקי מכון תקנים, תיקונים ולקוחות. המערכת רצה על Next.js ו־Node.js. הרשומות נשמרות בקובצי JSON בדיסק מקומי או ב־Vercel Blob פרטי, לפי סביבת ההפעלה.

## הפעלה מקומית

נדרשים Node.js 22.13 ומעלה ו־npm. ב־PowerShell או במסוף אינטראקטיבי אחר, מתוך תיקיית הפרויקט:

```sh
npm ci
npm run admin:create -- admin "מנהל מערכת"
npm run dev
```

פקודת יצירת המנהל מבקשת סיסמה מוסתרת של 12 תווים לפחות. אפשר להקים את החשבון מראש באמצעות משתנה הסביבה `CORTEZ_ADMIN_PASSWORD` שמוזרק לפקודה חד־פעמית. פתחו את [מסך הכניסה](http://localhost:3000) והתחברו. מנהל יכול ליצור משתמשים נוספים במסך ההגדרות. המערכת נפתחת עם נתונים ריקים.

עובדים יכולים לצפות ברשומות, ליצור ולעדכן אותן. מנהלים יכולים גם למחוק רשומות, לנהל משתמשים ולהפיק גיבויים. תיקון מקושר ללקוח לפי UUID, ומחיקת לקוח אפשרית לאחר הסרת התיקונים המשויכים לו.

## הפעלה בשרת

- הגדירו `CORTEZ_STORAGE_DIR` כנתיב מוחלט על דיסק מקומי מתמיד וניתן לכתיבה, למשל `/var/lib/cortez`. בהרצה מקומית ברירת המחדל היא `storage/` בתיקיית הפרויקט. הריצו את פקודת יצירת המנהל ואת השרת עם אותו נתיב.
- מאחורי פרוקסי HTTPS הגדירו `CORTEZ_ORIGIN` לכתובת הציבורית המדויקת, למשל `https://crm.example.com`. הפנו תעבורה לשרת Node יחיד, ובמידת הצורך הגדירו מגבלת גוף בקשה של לפחות 81 מ״ב בפרוקסי עבור העלאות מרובות.
- הריצו `npm ci`, `npm run build` ו־`npm start -- --hostname 127.0.0.1`. השתמשו במנהל שירותים שמפעיל מופע אחד של היישום. הפסיקו את השרת בזמן שימוש בפקודת המנהל מאותו דיסק, למשל בהקמה או בשחזור גישה.
- הגבילו את הרשאות תיקיית האחסון לחשבון השירות. שמרו אותה מחוץ ל־`public/` והוציאו אותה ממנגנון קבצים סטטיים של הפרוקסי.
- העלאות תומכות ב־JPG, PNG ו־WebP, עד 8 מ״ב לקובץ ועד 10 תמונות לרשומה. תמונות נשמרות כ־WebP ונשלפות דרך נתיב המחייב כניסה. כפתור הצילום משתמש בבורר המצלמה של המכשיר בדפדפנים התומכים בו.

מנוע האחסון מאמת רשומות עם Zod, מסדר פעולות כתיבה בתור ומחליף קבצים בצורה אטומית. המספור נשמר לפני כתיבת הרשומה, כך שכשל באמצע יצירה עשוי להשאיר דילוג בסדרה. רישום חשוד כשגיאה נשמר לבדיקה ונרשם ביומן השרת. האפליקציה מיועדת למופע יחיד עם נפח פעילות המתאים לקריאה וכתיבה של קובצי JSON שלמים.

## פריסה ב־Vercel

בפריסה ב־Vercel חברו לפרויקט מאגר Blob במצב **Private**. ההגדרה מזריקה לשרת את `BLOB_READ_WRITE_TOKEN`. מומלץ להשתמש במאגרים נפרדים לסביבת עבודה ולסביבת בדיקה. היישום שומר את הרשומות והמונה בקובץ `cortez/v1/state.json` עם כתיבה מותנית לפי ETag כדי למנוע דריסה משתי שמירות במקביל. הקבצים המקומיים בתיקיית `storage/` אינם חלק מחבילת הפריסה.

צרו פריסת בדיקה מפורשת עם `vercel deploy --environment preview`. ב־PowerShell, ליצירת חשבון מנהל ראשון במאגר הבדיקה של הפרויקט המקושר:

```powershell
$previewEnvPath = Join-Path $env:TEMP ('cortez-env-' + [guid]::NewGuid().ToString('N'))
try {
  vercel env pull $previewEnvPath --environment preview --yes
  if ($LASTEXITCODE -ne 0) { throw 'לא ניתן לטעון את הגדרות האחסון' }
  $env:CORTEZ_STORAGE_BACKEND = 'blob'
  node --env-file $previewEnvPath --import tsx scripts/create-admin.ts admin "מנהל מערכת"
} finally {
  Remove-Item Env:CORTEZ_STORAGE_BACKEND -ErrorAction SilentlyContinue
  Remove-Item -LiteralPath $previewEnvPath -ErrorAction SilentlyContinue
}
```

התמונות המקוריות עולות למאגר ישירות מהדפדפן באמצעות הרשאות קצרות מועד ומוגבלות לקובץ אחד. בעת השמירה, השרת בודק את תוכן הקובץ, ממיר אותו ל־WebP פרטי ומשייך אותו לרשומה. המקור הזמני נמחק לפי מדיניות תפוגה. תמונות שהוסרו נשארות פרטיות באחסון לצורך שחזור גיבויים קודמים, והאפליקציה מציגה רק תמונות המשויכות לרשומה קיימת.

גיבוי בענן יוצר עותק JSON ב־`cortez/v1/backups/` עם ההפניות לתמונות הפרטיות. לגיבוי בלתי תלוי העתיקו גם את אובייקטי התמונות למיקום פרטי אחר. לפני שחזור, עצרו כתיבות, שמרו עותק של המצב הנוכחי, ובדקו שהקבצים שאליהם מפנה הגיבוי זמינים. שחזרו את אובייקט `state.json` מתוך השדה `state` בגיבוי, עם סשנים ריקים והערך הגבוה ביותר לכל מונה בין המצב הנוכחי לגיבוי. בדקו כניסה, רשומות ותמונות לפני חידוש העבודה.

## גיבוי ושחזור

1. צרו גיבוי דרך **הגדרות › יצירת גיבוי**. כל גיבוי נשמר תחת `storage/backups/<id>/` (או תחת הנתיב שהוגדר) וכולל את קובצי הנתונים, התמונות וקובץ מניפסט. העתיקו מעת לעת גיבויים שהושלמו לדיסק נפרד ומוגן.
2. לפני שחזור, עצרו את השרת ושמרו עותק של תיקיית האחסון הנוכחית במקום מוגן. בחרו גיבוי שהושלם. במידת האפשר, בדקו אותו תחילה באמצעות מופע בדיקה עם תיקיית אחסון ופורט נפרדים.
3. הכינו תיקיית אחסון חדשה עם `data/` (כולל הקובץ המוסתר `.initialized`) ו־`uploads/` מתוך הגיבוי. קובץ הסשנים ייווצר מחדש בזמן האתחול ולכן כל המשתמשים ייכנסו שוב.
4. לפני הפעלה מחדש, עדכנו כל מונה ב־`data/counters.json` לערך הגבוה מבין הערך בגיבוי והערך האחרון שהוקצה בשרת הפעיל. אם הקובץ המקורי פגום, בררו את הערך הגבוה ממספור שנשמר, גיבויים ויומנים, לרבות מספרים של רשומות שנמחקו. המשיכו רק לאחר שנקבע חסם בטוח למספרים שהוקצו, כדי למנוע שימוש חוזר.
5. כוונו את `CORTEZ_STORAGE_DIR` לתיקייה המשוחזרת והפעילו מופע אחד. ודאו כניסה, ספירות, תיקונים משויכים ופתיחה של תמונות. באירוע קובץ JSON פגום, שמרו את הקובץ המקורי לצד עותק השחזור לצורך בדיקה.

## בדיקות

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run test:e2e
```

הבדיקה מקימה שרת מקומי עם אחסון זמני, בודקת מסכי דסקטופ ומובייל ב־Chrome ובודקת הישרדות נתונים ותמונות לאחר הפעלה מחדש. יש להתקין Chrome או להגדיר ערוץ Playwright באמצעות `CORTEZ_TEST_BROWSER` (למשל `msedge`). הנתונים והחשבונות בבדיקות נוצרים ונמחקים בתיקייה הזמנית.

הסמליל וצבעי המותג מבוססים על [האתר הרשמי של קורטז](https://cortez.co.il/).
